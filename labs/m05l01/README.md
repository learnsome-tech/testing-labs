### Your turn: define your gate

1. List the checks that must pass before merge.
2. Separate fast required checks from slower scheduled evidence.
3. Write the commands in the repository guide.

> **Hint:** A gate is useful when a new contributor can run it without tribal knowledge.

## Check yourself

- What does review add beyond automation?
- Which checks belong in a fast required gate?
- Who owns the explanation of a change?
- Why should gate commands be documented?
